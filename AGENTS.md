# Постоянные инструкции для разработки LagFinder (ветка `neoforge-1.21.1`)

Эти инструкции действуют для ветки `neoforge-1.21.1` и применяются при каждой задаче в ней.

1. Ветка `neoforge-1.21.1` — LagFinder для NeoForge 1.21.1 (ATM10): Mojang mappings, ModDevGradle, Java 21. Ветки `Setup` (1.7.10 / GTNH) и `master` из этой ветки не изменять.
2. Работать в ветке `neoforge-1.21.1`. Перед изменениями проверять текущую ветку.
3. Не создавать дополнительные ветки и Pull Request без запроса пользователя.
4. Gradle запускается любым JDK 21+; мод собирается под Java 21 (toolchain). Не повышать целевую версию Java из-за версии JDK, которой запускается Gradle.
5. После изменения исходников запускать `.\gradlew.bat clean build`. Для проверки в игре — `.\gradlew.bat runServer` и `.\gradlew.bat runClient` (клиент работает в `run-client`); с AE2 — добавить `-PdevMods=<папка mods сборки ATM10>` (из неё берутся appliedenergistics2 и guideme).
6. Если сборка не удалась, исправлять ошибки и повторять сборку до успешного результата.
7. После успешной сборки проверять `git diff` и создавать коммит с понятным английским названием. `git push` выполнять только после подтверждения пользователя.
8. Не отправлять изменения, если сборка не прошла.
9. Не добавлять поясняющие комментарии в Java-код.
10. Не удалять существующие функции без необходимости.
11. Проверять совместимость клиентской и серверной частей мода: канал сообщений необязательный, клиент с модом заходит на сервер без мода и наоборот.
12. Все серверные диагностические функции должны проверять права на сервере через NeoForge PermissionAPI: узлы `lagfinder.scan` и `lagfinder.teleport` (по умолчанию — OP и владелец одиночного мира; LuckPerms может выдавать их рангам).
13. Не использовать force push. Не коммитить результаты сборки, папки `run`/`run-client`, токены и конфиденциальные файлы.
14. При изменении сетевого протокола проверять безопасность пакетов (размеры, права) и совместимость клиентской и серверной сторон.
15. После каждой задачи сообщать изменённые файлы, результаты тестов и SHA коммита. Если проверка не запускалась или коммит не создан, явно сообщать об этом.
