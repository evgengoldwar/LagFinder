# Постоянные инструкции для разработки LagFinder

Эти инструкции действуют для всего репозитория и применяются при каждой задаче.

1. Проект — LagFinder для GTNH 2.9 и Minecraft 1.7.10.
2. Основная рабочая ветка — `Setup`. Никогда не изменять `master`. Перед изменениями проверять текущую ветку.
3. Работать непосредственно в `Setup`. Не создавать дополнительные ветки и Pull Request без запроса пользователя.
4. Для запуска Gradle использовать JDK 25. Сохранять совместимость мода с целевой версией Java, установленной проектом; не повышать её из-за версии JDK, используемой для запуска Gradle.
5. После изменения исходников последовательно запускать `.\gradlew.bat spotlessApply` и `.\gradlew.bat clean build`.
6. Если сборка не удалась, исправлять ошибки и повторять сборку до успешного результата.
7. После успешной сборки проверять `git diff`, создавать коммит с понятным английским названием и выполнять `git push origin Setup`.
8. Не отправлять изменения, если сборка не прошла.
9. Не добавлять поясняющие комментарии в Java-код.
10. Не удалять существующие функции без необходимости.
11. Проверять совместимость клиентской и серверной частей мода.
12. Все серверные диагностические функции должны проверять права на сервере: пользователь должен быть OP либо иметь разрешение через ранг ServerUtilities с префиксом `lagfinder_*`.
13. Не использовать force push. Не коммитить результаты сборки, токены и конфиденциальные файлы.
14. При изменении сетевого протокола проверять безопасность пакетов и совместимость клиентской и серверной сторон.
15. После каждой задачи сообщать изменённые файлы, результаты тестов и SHA коммита. Если проверка не запускалась или коммит не создан, явно сообщать об этом.

## Первоначальное добавление инструкций

Создать для этого файла отдельный коммит в `Setup`. Перед первым push запросить явное подтверждение пользователя и дождаться ответа. После подтверждённого первого push выполнять последующие push согласно правилам выше без повторного запроса, если пользователь не установит иные ограничения.
